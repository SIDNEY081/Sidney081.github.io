AI Stroke Shield

Predicting stroke risk from everyday health indicators with a gradient-boosted classifier

Live Demo Source Code

The problem

Stroke risk is driven by a handful of measurable, everyday indicators - age, BMI, glucose level, smoking status, hypertension, and heart disease history - but connecting those dots quickly usually depends on a clinician manually weighing each factor. AI Stroke Shield turns that into a fast, structured risk estimate: enter a patient's indicators, get a prediction and probability back immediately, aimed at supporting earlier detection rather than replacing clinical judgment.

The data

Trained on the public Kaggle stroke-prediction dataset, using gender, age, hypertension, heart disease, marital status, work type, residence type, average glucose level, BMI, and smoking status. Missing BMI values were handled with mean imputation. The dataset is heavily imbalanced - most patients in the data haven't had a stroke - so the minority (stroke) class was resampled before training rather than left as-is, which matters here: an untouched imbalanced dataset lets a model score well by mostly predicting "no stroke," which is exactly the wrong failure mode for a screening tool.

Why XGBoost

XGBoost was chosen for the same reason it's a common default on structured/tabular clinical data like this: it handles a mix of continuous (glucose, BMI, age) and categorical (work type, smoking status) features without heavy preprocessing, and it's fast enough to retrain and iterate on during development. The model was trained on an 80/20 split and serialized with joblib for reuse in the deployed app rather than retraining on every prediction.

Evaluating a screening tool honestly

Accuracy alone is a weak metric for an imbalanced medical dataset, so evaluation includes precision, recall, and F1-score alongside it, plus a confusion matrix, ROC curve, precision-recall curve, and a feature-importance plot to see which indicators actually drove predictions. For a tool like this, recall on the positive class matters more than raw accuracy - missing an at-risk patient is a worse failure than a false alarm that gets double-checked.

From notebook to app

The trained model is wrapped in a Streamlit interface: dropdowns and numeric fields for each indicator, a "Predict Stroke" action, and a result that shows both the prediction and its probability - not just a bare yes/no, so the number carries as much information as the label does.
